== 3. THE PROJECT AND HOW TO EDIT IT ==
Monorepo: `backend/` (NestJS + MongoDB + Redis + BullMQ), `apps/admin_app`, `apps/client_portal` (operator portal), `apps/customer_app`, `apps/driver_app` (Flutter, web is used for testing), `packages/shared_*` (Flutter, owned by Session A: do not edit), `documentation/` (the master plan is `documentation/abra-master-plan.md`; `prototypes/*.html` are the design specification).
- Backend modules live in `backend/src/modules/<name>/`. The "three-file rule": each feature keeps its schema/types, controller and service in its own files (`*_client_manage.ts` = controller + schemas + zod, `*_client_manage.service.ts` = logic). Tests sit in `<module>/tests/` (`*.spec.ts` unit, `*.e2e-spec.ts` against a real local Mongo).
- Every write goes through `AuditedChangeRunner` (audit log). Money is integer paise. Errors are `ApiException(code, plain message)`; messages are shown to the owner as written, so keep them short and plain English.
- Operators only see their own data (`actor.operatorId`); admin sees all. Permissions use `@RequirePermission('buses.update')` etc.
- Flutter screens: models, state (Riverpod providers), API calls and widgets in the screen's own file. API client: `ref.read(appDependenciesProvider).apiClient` (get/post/put/patch/delete/postForm/getBytes). No sample or fake data. A screen needs a real loading, empty, error-with-Retry and "no access" state.
- SHARED FILES (Session A owns, do not edit; list any change you need under "Shared changes I need"): `apps/*/lib/routing/`, `apps/*/lib/app/providers.dart`, `apps/admin_app/lib/shell/admin_shell.dart`, `lib/l10n/*_strings.dart` and `l10n/*.arb`, `packages/shared_*`, `backend/src/modules/rbac/**`, `domain-modules.ts`, `app.module.ts`, config. New backend modules: put the module in your own folder and tell Session A how to register it.
- Do NOT use heredocs with `$` or backslashes through the shell to write Dart; write scripts to a file first. Some editors in this environment turn `\uFEFF` and `\n` escapes into real characters, which breaks lint and Dart strings: build such characters with `String.fromCharCode(...)` / `chr(...)`.
